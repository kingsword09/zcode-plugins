# 从 tsdown+esbuild 迁移到 vite（library mode）+ @stylexjs/unplugin

用 vite 替代两处构建：web 前端（React+StyleX）走标准 `vite build`，node 端 MCP server 走 vite library mode。`@stylexjs/unplugin` 的 vite 插件替代当前手写的 esbuild babel 集成（`esbuild.config.ts` / `esbuild.stylex.ts` / `esbuild.assets.ts` 全部删除）。

## 改动范围

### 删除
- `esbuild.config.ts` / `esbuild.stylex.ts` / `esbuild.assets.ts`
- `src/ui/assets.ts`（改为运行时读 vite 构建产物）
- `package.json` 里 `@babel/core` / `@babel/preset-typescript` / `@babel/plugin-syntax-jsx` / `esbuild` / `tsdown` 等 devDeps
- `tsdown.config.ts`
- `tsconfig.web.json`（合并进主 tsconfig）

### 新增/改写
- `vite.config.ts`（项目根，单一配置）
  - 两个 build target：`web`（IIFE，React+StyleX，输出 `.cache/web/main.js`+`.css`）和 `mcp`（library mode，external MCP SDK，输出 `dist/mcp/server.js`）
  - plugins：`@vitejs/plugin-react`（jsx）+ `@stylexjs/unplugin`（stylex，放在 react 之前）+ `vite-plugin-static-copy` 或自定义 plugin（把 web 产物内联成 `src/ui/assets.ts`）
  - `resolve.alias`：`@shared` → `src/shared`（统一 web 和 node 的类型导入路径，去掉现在 `../src/shared/types` 这种跨层引用）
  - `build.rollupOptions.external`：node target 外置 `@modelcontextprotocol/sdk`、`zod` 等依赖；web target 外置无（IIFE 自包含）
- `package.json`
  - devDeps：`vite`、`@vitejs/plugin-react`、`@stylexjs/unplugin`、`@types/react`、`@types/react-dom`、`react`、`react-dom`、`typescript`（保留 `@modelcontextprotocol/sdk`、`zod`）
  - scripts：`build:web` = `vite build --mode web`、`build:node` = `vite build --mode node`、`build` = 两步串联、`typecheck` = `tsc --noEmit`、`test` = `bun test`
- `web/api.ts` + `web/App.tsx` + `web/components/*.tsx`：把 `import ... from "../src/shared/types"` / `"../../src/shared/types"` 改为 `from "@shared/types"`（alias 后可跨层干净引用）
- `src/ui/server.ts`：`WEB_HTML` 来源从 `./assets.ts`（编译期内联）改为**运行时读取** vite 产物文件。两种实现择一：
  - (a) 构建后产物放 `dist/web/index.html`，server.ts 用 `fs.readFileSync(path.join(__dirname, '..', 'web', 'index.html'))` 读（tsdown 时内联，vite library 下需要文件随行；`files` 字段带上 dist/web）
  - (b) 仍用生成 `src/ui/assets.ts`：写一个 vite 插件 `inlineAssetsPlugin`，在 `generateBundle` 钩子里读 `main.js`+`main.css`，emit 一个 `assets.ts` 到源码树（保留 gitignore）。**选 (b)**，保持「单一 server bundle 自包含」的优势，不动 `plugin.json` 的 `${ZCODE_PLUGIN_ROOT}/dist/mcp/server.js` 路径
- `tsconfig.json`：`include` 加 `web/**/*.ts*`；不再需要 `tsconfig.web.json`
- `src/mcp/server.ts`、`src/ui/server.ts`、`src/config/*.ts`、`src/modelsdev/*.ts`：tsdown → vite 后，`allowImportingTsExtensions` 仍保留（vite 用 esbuild/rolldown 不受 ts `paths` 影响，但 tsc 需要 `paths` 配 `@shared`）

### Vite 配置要点

```ts
// vite.config.ts
import { defineConfig } from 'vite';
import react from '@vitejs/plugin-react';
import stylex from '@stylexjs/unplugin';
import { inlineAssetsPlugin } from './scripts/vite-inline-assets.ts';

export default defineConfig(({ mode }) => ({
  plugins: [
    stylex.vite({ useCSSLayers: true, unstable_moduleResolution: { type: 'commonJS', rootDir: 'web' } }),
    react(),
    mode === 'web' && inlineAssetsPlugin({ outPath: 'src/ui/assets.ts' }),
  ].filter(Boolean),
  resolve: { alias: { '@shared': '/src/shared' } },
  build: mode === 'web' ? {
    lib: { entry: 'web/main.tsx', formats: ['iife'], name: 'ZCodeModelConfig', fileName: () => 'main.js' },
    outDir: '.cache/web', emptyOutDir: true, cssCodeSplit: false, sourcemap: false, minify: true,
  } : {
    lib: { entry: 'src/mcp/server.ts', formats: ['es'], fileName: () => 'mcp/server.js' },
    outDir: 'dist', emptyOutDir: true, sourcemap: false, minify: false, target: 'node24',
    rollupOptions: { external: ['@modelcontextprotocol/sdk', 'zod', /^node:/], output: { entryFileNames: 'mcp/server.js' } },
  },
}));
```

`inlineAssetsPlugin`（新建 `scripts/vite-inline-assets.ts`）：`generateBundle` 钩子读取 bundle 的 `main.js` 和 CSS asset，拼成 `WEB_HTML` 字符串，写入 `src/ui/assets.ts`。这复刻当前 `esbuild.assets.ts` 的行为，只是换成 vite 插件 API。

### 构建顺序

`vite build --mode web` → 生成 `.cache/web/main.{js,css}` + `src/ui/assets.ts`；`vite build --mode node` → 读 assets.ts（作为普通源码导入）→ 产出 `dist/mcp/server.js`（含内联 HTML）。类型检查和 `bun test` 不变。

### 风险与验证

- vite library mode 对 node 纯 server 库的外置比 tsdown 需要更多手动配置（`external` 正则、`node:` 前缀）；tsdown 的 `neverBundle` 一行搞定。用 `rollupOptions.external: [/^node:/, '@modelcontextprotocol/sdk', 'zod']` 覆盖。
- `@stylexjs/unplugin` 的 `unstable_moduleResolution.rootDir` 要指向 `web/`，否则跨文件 style 引用解析会失败（当前手写 babel 也踩过这个坑）。
- `tsconfig.web.json` 合并进主 `tsconfig` 后，`jsx: react-jsx` + `lib: ['ES2023','DOM']` 会应用到全项目；node 代码用 DOM 类型无副作用，但要把 `types` 保留 `@types/bun`。

### 验证步骤
1. `bun install`
2. `bun run typecheck && bun run build`（web + node 两阶段）
3. `bun test`
4. 重启 dev-server，curl `/api/state` + 浏览器跑一遍配置流程（复用上次验证路径）
